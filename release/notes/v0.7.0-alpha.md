Atelier installed with a free Apple ID now renews and updates itself with that Apple ID, and after the iPhone-only installer it opens already signed in, reusing the installer's certificate. Atelier no longer keeps your Apple ID's password, only Apple's sign-in token, and asks you to Sign In Again once that ends. Apps signed with a certificate that comes with App Groups keep theirs, and the website can install Atelier with your certificate from a computer.

## New

- Atelier installed with a free Apple ID renews itself every week, and signs its own updates and Custom Install… with that Apple ID, once you sign in with it in Atelier. Until then, it's in the Library's Renew section with Sign In (#3).
- After the [iPhone-only installer](https://github.com/atelierstore/atelier-install), Atelier is signed in from the start: on first open it signs in by itself with the Apple ID the installer used, as the same device to Apple so it shouldn't ask for a code again, and reuses the installer's certificate instead of making a second one, since a free Apple ID only gets two. If Apple still asks for a code, or the sign-in fails, the Sign In sheet opens already filled in. When Apple still counts a certificate you just revoked, Atelier offers the remaining ones again as Revoke Another? instead of stopping, as revoking another frees a place where waiting doesn't (#17).
- Atelier no longer keeps your Apple ID's password. Your password only goes to Apple, and Atelier keeps Apple's sign-in token in the Keychain instead, which signs in again for installs, Check Now and the weekly renewals, without the password or a code, until the date on the Apple ID's page. A renewal in the background goes ahead with the token even after Apple asked for a code. When the sign-in expires, Install, Renew and Check Now open Sign In Again, which the Apple ID's page has too, and a renewal in the background says so in one notification. Apple ID Log says how long Apple says each token lasts. From its version 0.2.0, the iPhone-only installer hands Atelier the token too, rather than the password (#23, #25).
- Re-sign on an app installed with an Apple ID whose certificate Apple revoked or that ended gets that Apple ID a new certificate, signing in again, then signs the app again with it, even when another certificate is in use. The app is installed over, rather than deleted first, and keeps its data. The Apple ID's page has New Certificate too, so you don't sign out and in again (#21).
- Apps signed with a certificate that comes with App Groups, as signing services' often do, keep theirs too: Atelier keeps each app's App Groups in a folder of its own in one of the certificate's, so its widgets and extensions see the app's data. Other apps signed with that certificate could read the folder. Custom Install › Advanced › Share App Groups turns it off for an app (#2).
- The website installs Atelier with your certificate from a computer too: it signs Atelier there and shows a QR code, which opens iOS's install alert on your iPhone (#11).
- The website's Get Atelier lists AltStore PAL as planned, and recommends it first to visitors in the EU, Japan and Brazil, where Apple allows it (#7).
- The website counts visits and taps per day, with no cookies and nothing that identifies visitors, and shows them on a private Stats page. Its privacy answers now say what's counted (#19).

## Fixes

- Settings says where its badge comes from: under Certificates, a line names the certificate or Apple ID that's revoked, expired or about to expire, and how many others there are, as in "you@example.com is revoked, and 2 other issues". Before, Settings only named the certificate in use, so one revoked that wasn't in use showed nowhere (#26).
- When a source's GitHub repo doesn't have the branch or file the source points to, Atelier says which is missing, instead of saying your GitHub account can't see the repo. For a public repo, it no longer asks you to sign in (#13).
- An offloaded app stays in Offloaded while another app installs. Before, an install could take the install check the offloaded app still held, so the offloaded app briefly showed in Installed with "Data not put back" (#18).
- An app being re-signed shows once, in its own row in Re-sign, with its progress and the ring that stops it, rather than in Downloads too. It stays in Re-sign while it's deleted to be installed again. Reinstall and Custom Install… show in the app's row the same way. "Re-signed just now", "Updated just now" and "Renewed" stay on one line (#20).
- Apple's sign-in and developer errors are in plain words, without Apple's code or Atelier's steps, which Apple ID Log keeps. A wrong password says so, and Atelier no longer tries it through its other sign-in servers. A wrong verification code says "That code wasn't right." Otherwise Atelier quotes Apple's own sentence, or says Apple wasn't reached and to check your connection. "Reinstall required" stays on one line (#25).

## Updating from 0.6.0-alpha

Installed with a certificate, Atelier's update shows in the Library. You can also install this IPA over it, signed with the same certificate and profile; your apps, certificates and settings stay.

Installed with a free Apple ID, Atelier 0.6.0 can't sign its own update. Install this IPA over it the way you installed it, with the same tool and Apple ID, so it keeps your apps and settings. Then sign in with that Apple ID in Atelier, from the Library's Renew section, and from then on Atelier renews and updates itself.

Apple IDs you signed in with before stay signed in. The next time Atelier signs in to Apple with one, for an install, a renewal or Check Now, it uses the password it kept one last time, keeps Apple's token, and deletes the password.

## Installing

Get Atelier from [its website](https://atelierstore.app), or sign the IPA below with your own certificate or Apple ID and install it with a tool such as Sideloadly, Feather, AltStore or SideStore ([guide](https://github.com/atelierstore/Atelier/blob/main/docs/install.md)). Requires iOS 17 or later.

## Known limits

- Background installs and automatic updates need Wi-Fi and LocalDevVPN, and renewing needs LocalDevVPN.
- Apps signed with an Apple ID only install through the setup (Settings › Installs › Setup).
- A free Apple ID allows 3 apps at a time on your iPhone, Atelier included when it's signed with one, and 10 new apps a week. Renewing an app takes one of the 10 again once its App ID has ended, about every 10 days.
- Apple has refused some free Apple ID sign-ins on and off since October (error -80045 in Apple ID Log).
- Atelier updates itself only with the Apple ID that installed it, or with a profile for the App ID it was installed with.
- Atelier's releases are pre-releases for now, so keep Include Pre-releases on for its source.
